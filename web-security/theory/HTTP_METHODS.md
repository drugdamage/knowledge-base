# Методы HTTP-запросов

Метод HTTP указывает, что клиент просит сделать с ресурсом. В строке `GET /tasks/42 HTTP/1.1` метод стоит первым.

## Назначение и примеры

| Метод | Что запрашивает клиент | Пример |
| --- | --- | --- |
| `GET` | Получить данные ресурса. | `GET /tasks/42` возвращает данные задачи. |
| `HEAD` | Получить заголовки ответа, который сервер отправил бы на `GET`. Тело ответа отсутствует. | `HEAD /tasks/42` позволяет посмотреть тип данных в `Content-Type`. |
| `POST` | Передать данные серверу для обработки. | `POST /tasks` отправляет данные новой задачи. Сервер создаёт задачу и выбирает её адрес. |
| `PUT` | Создать или заменить ресурс по указанному адресу, передав его полное представление. | `PUT /tasks/42` задаёт название, описание и статус задачи. |
| `PATCH` | Применить к ресурсу указанные изменения. | `PATCH /tasks/42` меняет статус задачи и сохраняет остальные поля. |
| `DELETE` | Удалить связь между адресом и ресурсом. | `DELETE /tasks/42` убирает задачу из списка и делает её недоступной по прежнему адресу. |
| `OPTIONS` | Узнать, какие возможности доступны для ресурса или сервера в целом. | `OPTIONS /tasks/42` может вернуть список поддерживаемых методов в заголовке `Allow`. |
| `CONNECT` | Открыть туннель через прокси. | Через такой туннель браузер может установить TLS-соединение с сайтом. |
| `TRACE` | Посмотреть, в каком виде запрос дошёл до получателя. | При диагностике ответ может показать заголовки, которые получил сервер. |

## Безопасность и идемпотентность

**Безопасные методы** предназначены для чтения или диагностики без запроса на изменение состояния ресурса. К ним относятся `GET`, `HEAD`, `OPTIONS` и `TRACE`.

**Идемпотентный метод** даёт одинаковый предусмотренный эффект при одном запросе и при повторе того же запроса. К таким методам относятся все безопасные методы, а также `PUT` и `DELETE`. Код ответа может измениться. Первый `DELETE /tasks/42` может вернуть `204`, а повторный — `404`, потому что задача уже удалена.

Повтор `POST /tasks` может создать ещё одну задачу. Для `PATCH` важен смысл изменения. Установка статуса «выполнена» даст тот же итог при каждом повторе, а увеличение счётчика на единицу изменит его снова.
