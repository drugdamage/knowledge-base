# Практика

## Практика CSRF

Лабораторная CSRF vulnerability with no defenses выполнена. Цель — изменить email учебной жертвы через внешнюю HTML-страницу.

Вошёл в учебный аккаунт и изменил почту через сайт. В Burp, в Proxy → HTTP history, нашёл `POST`-запрос на `/my-account/change-email`. Разобрал параметр `email` в теле запроса: справа от знака `=` передаётся новая почта.

Отправил запрос в Repeater, изменил `email` и нажал Send. Получил `302`, то есть перенаправление. Обновил My account и увидел новую почту. Так проверил результат изменения запроса.

Создал HTML-форму с методом `POST`, адресом обработчика в `action` и полем `email`. Скрипт `document.forms[0].submit()` автоматически отправляет форму при открытии страницы.

Разместил HTML на Exploit server, сохранил и проверил его. Затем указал почту, отличающуюся от почты моего аккаунта, и доставил страницу учебной жертве. Лабораторная успешно завершена.

Браузер жертвы отправляет запрос с её cookie, если правила cookie это разрешают. Знать значение cookie не требуется. Изменение почты через Repeater проверяет обработчик; изменение через внешнюю страницу в сессии жертвы демонстрирует CSRF.

## Практика SSRF

Выполнены две лабораторные PortSwigger по SSRF, включая Basic SSRF against another back-end system. В них отработал изменение адреса, по которому сервер обращается за данными.

Работал с функцией проверки наличия товара. В запросе нашёл `stockApi`: это параметр в теле запроса, содержащий адрес для последующего обращения сервера. В Repeater можно изменять его значение и сравнивать ответы.

Разобрал два отдельных запроса. Сначала мой браузер или Repeater обращается к магазину. Затем сам сервер магазина обращается по адресу из `stockApi`. Путь после `POST` и заголовок `Host` относятся к первому запросу.

В лабораторной с другим внутренним сервером использовал Intruder для перебора последнего числа в адресе `192.168.0.X`. Он подставляет значения из заданного диапазона и отправляет запросы автоматически, чтобы найти нужный сервис.

При разборе результатов учитывал код ответа и его содержимое. Ответ `200` с обычной страницей магазина сам по себе не подтверждает SSRF. Нужно установить, что сервер выполнил непредусмотренный запрос по подставленному адресу.

Подтверждением могут быть данные целевого сервиса в ответе либо связанная с проверкой запись в его журнале. Отображение ответа необязательно: сервер может выполнить запрос, не показывая его результат пользователю. Обе лабораторные завершены успешно.
