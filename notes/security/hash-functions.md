# Что такое хэш-функция и как она работает

## Коротко

**Хэш-функция** вычисляет по входным данным некоторое значение — **хэш**. Например, SHA-256 получает данные разной длины и выдаёт 256 бит: 32 байта, обычно записываемые как 64 шестнадцатеричных символа. При одинаковых входных байтах один и тот же алгоритм всегда даёт одинаковый результат. [NIST: хэш-функции](https://csrc.nist.gov/projects/hash-functions), [MDN: digest](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest)

Хэш-функции бывают и некриптографическими, например для хэш-таблиц. Дальше речь о **криптографических** хэш-функциях, на примере SHA-256.

## Как это работает

Упрощённая схема SHA-256:

1. Текст переводится в байты; для файла используются его байты.
2. Сообщение дополняется по правилам алгоритма и делится на блоки по 512 бит.
3. Каждый блок проходит через последовательность побитовых операций и сложений, меняющих внутреннее состояние.
4. Итоговое состояние становится 256-битным хэшем.

Это схема именно SHA-256: другие алгоритмы могут быть устроены иначе. [RFC 6234, разделы 4–6](https://www.rfc-editor.org/rfc/rfc6234.html)

## Пример на Python

```python
import hashlib

for text in ("hello", "Hello"):
    digest = hashlib.sha256(text.encode("utf-8")).hexdigest()
    print(f"{text}: {digest}")
```

Результат:

```text
hello: 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
Hello: 185f8db32271fe25f561a6fc938b2e264306ec304eda518007d1764826381969
```

Одна изменённая буква дала совсем другой результат. Пробел или перевод строки тоже меняет входные байты. [Документация Python: hashlib](https://docs.python.org/3/library/hashlib.html)

## Какие свойства нужны

- **Стойкость к поиску прообраза:** по хэшу должно быть вычислительно трудно подобрать вход, который его даёт.
- **Стойкость ко второму прообразу:** для заданного сообщения трудно найти другое с тем же хэшем.
- **Стойкость к коллизиям:** трудно найти любую пару разных сообщений с одинаковым хэшем.

Коллизии возможны: множество входов больше множества хэшей фиксированной длины. Требование состоит в сложности их поиска. [NIST: свойства стойкости](https://csrc.nist.gov/projects/hash-functions)

## Где применяется и что легко перепутать

**Проверка файла.** Можно вычислить хэш скачанного файла и сравнить с ожидаемым. Эталон должен приходить из доверенного источника: если подменены и файл, и опубликованный хэш, само сравнение подмену не обнаружит.

**Хэширование и шифрование.** У хэширования нет операции расшифрования с ключом. При этом короткий или предсказуемый вход можно угадать перебором: вычислять хэши вариантов и сравнивать. [RFC 6234, раздел 1](https://www.rfc-editor.org/rfc/rfc6234.html)

**Пароли.** Для хранения паролей применяют специальные затратные схемы, например Argon2id с индивидуальной солью и выбранными параметрами затрат. Одиночный SHA-256 слишком быстр для этой задачи. Соль не является секретом и не отменяет перебор. [RFC 9106: Argon2](https://www.rfc-editor.org/rfc/rfc9106.html)
