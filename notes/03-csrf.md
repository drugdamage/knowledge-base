# CSRF

CSRF — уязвимость, при которой посторонняя страница может побудить браузер пользователя выполнить нежелательное действие на другом сайте от имени пользователя.

## Механизм в схеме с сессионной cookie

1. Пользователь уже вошёл в аккаунт целевого сайта.
2. Он открывает страницу, способную инициировать нужный запрос с известными или предсказуемыми параметрами.
3. Браузер прикладывает сессионную cookie, если правила её отправки это допускают.
4. При отсутствии действенной защиты целевой сайт может принять нежелательный запрос как обычное действие пользователя.

Запрос к целевому сайту выполняет браузер. Злоумышленнику не требуется знать идентификатор сессии: браузер передаёт cookie целевому сайту.

## Форма

Форма содержит поля ввода, например новую почту, и позволяет передать их значения обработчику. Куда отправлять данные, задаёт страница. Обычные HTML-формы могут обращаться и к другому сайту.

При сохранении почты браузер передаёт данные формы серверу. Сервер должен проверить запрос до изменения данных.

## CSRF-токен

В распространённой схеме сервер создаёт непредсказуемый токен, связывает его с сессией и передаёт в форму. При отправке формы токен приходит отдельным полем вместе с остальными данными. Возможна передача через код приложения в заголовке запроса.

Сервер проверяет ожидаемый токен. Если обязательный токен отсутствует или неверен, действие должно быть отклонено до изменения данных. Пользователь токен вручную обычно не вводит.

Токен может выдаваться на сессию или на отдельный запрос. Его создание не обязательно совпадает с авторизацией. Ограничения браузера обычно не позволяют посторонней странице прочитать токен с другого сайта.

## SameSite

SameSite — атрибут cookie. Сервер задаёт его через `Set-Cookie`, а браузер применяет при решении об отправке cookie. Поведение зависит от значения атрибута и контекста запроса.

Если правило запрещает отправку сессионной cookie, запрос может дойти до сервера без неё. В рассматриваемой схеме сервер не распознает вошедшего пользователя и должен отклонить изменение его данных.

Отсутствие cookie само по себе не означает постороннюю сессию. Например, cookie могла истечь. SameSite регулирует отправку cookie; проверку токена выполняет сервер.

## Отличие от SSRF

- При SSRF непредусмотренный запрос выполняет сервер приложения.
- При CSRF нежелательный запрос к сайту выполняет браузер пользователя.
