# SSRF

SSRF — уязвимость, позволяющая через приложение заставить сервер обратиться к ресурсу, обращения к которому эта функция не должна допускать.

## Кто отправляет запрос

В примере магазина браузер обращается к серверу магазина. По логике функции сервер магазина запрашивает сведения у сервиса склада и возвращает результат браузеру. Запрос к складу выполняет сервер магазина.

Само обращение сервера к другому сервису — нормальная возможность приложения. Уязвимость возникает, когда пользователь может направить это обращение к недопустимому для функции ресурсу.

## Возможные последствия

Сервер может иметь сетевой доступ к внутренним сервисам, недоступным посетителю напрямую. В зависимости от доступных ресурсов и их защиты SSRF может привести к раскрытию данных или нежелательным действиям.

## Основные меры защиты

- Проверка адреса назначения сервером по списку разрешённых сервисов — **allowlist**, когда необходимые назначения заранее известны.
- Ограничение сетевых соединений приложения только необходимыми сервисами.

Allowlist задаёт допустимые назначения для конкретной функции. В разобранной схеме адрес проверяет сервер приложения. Браузер эту проверку за него не выполняет.

## Что считать доказательством

Нужно подтвердить, что пользователь смог вызвать непредусмотренное серверное обращение. Адрес назначения не обязательно отображается в ответе браузеру.

Наличие URL в параметре и ответ `200 OK` сами по себе не подтверждают SSRF. Обращение ко второму складу, если оба склада предусмотрены функцией, — нормальное поведение.

Обычный ответ страницы не доказывает отсутствие уязвимости. В выполненной проверке зафиксирован штатный запрос; SSRF не подтверждена, её отсутствие также не установлено.
