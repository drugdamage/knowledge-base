# Моя практика

## Повтор запроса проверки наличия товара в Burp Suite

**Статус:** выполненная учебная проверка обычного HTTP-запроса.

### Цель

Найти запрос проверки наличия товара, повторно отправить его через Repeater и прочитать ответ сервера.

### Окружение

- PortSwigger Web Security Academy: учебный магазин лаборатории по SSRF.
- Burp Suite Community Edition и встроенный Burp Browser.
- Запрос `POST /product/stock`; в теле обнаружен параметр `stockApi`.

### Шаги

1. Открыть учебный магазин через страницу лаборатории Web Security Academy.
2. Скопировать адрес магазина во встроенный Burp Browser и перейти по нему.
3. Открыть произвольный товар и нажать **Check stock**.
4. В Burp Suite перейти в **Proxy → HTTP history**.
5. Найти запрос `POST /product/stock` и просмотреть его содержимое.
6. Нажать на запрос правой кнопкой мыши и выбрать **Send to Repeater**.
7. Открыть **Repeater** и отправить запрос кнопкой **Send**, без изменения его данных.
8. Прочитать статус и тело во вкладке **Response**.

### Ожидаемый результат

Получить сведения о количестве выбранного товара на выбранном складе.

### Фактический результат

- HTTP-статус: `200 OK`.
- Тело ответа: `170`.

В контексте функции значение `170` интерпретируется как количество доступных единиц товара. В просмотренном ответе тело отделено от заголовков пустой строкой.

Результат записан вручную по выполненной проверке. Полный HTTP-экспорт и снимки экрана в этот отчёт не включены.

### Вывод

Найден и повторно отправлен штатный запрос проверки наличия; получен ответ `200 OK` с телом `170`.

SSRF этой проверкой не подтверждена. Отсутствие уязвимости также не установлено. Внутренний адрес назначения и наличие проверки allowlist отдельно не исследовались. По одному ответу нельзя достоверно установить внутренний маршрут запроса.

## Условная задача: изменение почты без CSRF-токена при ответе 403

**Статус:** разбор условной учебной задачи. Практический тест на сайте не выполнялся.

### Условия задачи

Пользователь авторизован. Для операции смены почты требуется CSRF-токен. В задаче дан запрос без обязательного токена; после получения ответа профиль обновлён для проверки состояния аккаунта.

### Ожидаемый результат

Сервер должен отклонить запрос без обязательного CSRF-токена до выполнения операции. Почта в аккаунте должна остаться прежней.

### Фактический результат по условию

Сервер вернул `403 Forbidden`, но после обновления профиля отображается новая почта.

### Вывод

В условиях задачи действие не было предотвращено: почта изменилась при отсутствии обязательного токена. Сообщение об ошибке не равно отказу в изменении данных.

В задаче оценивается обработка обязательного токена. Отдельное подтверждение межсайтовой отправки запроса браузером не входит в её условия.

### Возможное воздействие

Изменение почты может создать риск восстановления пароля через адрес злоумышленника, захвата аккаунта и действий от имени пользователя. Эти последствия зависят от механизма восстановления и других проверок сервиса; они не воспроизводились в данном разборе.

### Направление исправления

Проверять наличие и корректность CSRF-токена до изменения данных. При отказе адрес почты должен оставаться прежним. Результат проверки следует оценивать по ответу сервера и фактическому состоянию профиля.
